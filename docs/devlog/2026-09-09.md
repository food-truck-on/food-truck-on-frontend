## 판단

### 렌더링을 Next.js로 정했다

`product-rules.md`가 카카오톡 OG 미리보기를 필수로 규정하고 있다.
OG 태그는 **서버가 HTML을 만들어 줘야** 뜨는데, Vite CSR로 가면 크롤러가 빈 HTML을 받아간다.
Vite를 쓰면 `/t/:slug`용 서버를 따로 세워야 해서 **배포 대상이 둘로 늘어난다.**
마감이 17일 남은 상황에서 배포처를 둘로 늘리는 건 비용이 크다고 봤다.

백엔드가 Node.js인 것과는 무관한 결정이다. 백엔드는 `/api/v1` JSON만 내려주고,
Next.js는 화면 HTML만 만든다. 서로 HTTP로 대화하는 별개 프로그램이다.

### 마감은 수동으로만 간다

A(자동 종료) / B(수동) / C(둘 다) 중 B를 골랐다.
백엔드에 이미 `POST /sessions/:sessionId/close`만 있고 자동 종료 로직은 없다.
**B로 가면 백엔드 추가 작업이 0이고, 내 작업은 `홈 / 영업 중` 화면 하나 그리는 것뿐이다.**
A나 C는 백엔드 작업을 새로 요청해야 하는데, 남은 일정에서 그 값이 크지 않다고 봤다.

대신 규칙을 하나 박아뒀다 — **마감 시각이 지나도 프론트가 상태를 바꾸지 않는다.**
시각을 비교해서 "종료"로 바꾸면 서버 상태와 어긋난다. 마감 시각은 안내 문구일 뿐이다.

### 화면보다 컴포넌트를 먼저 만들었다

9/8 계획이 통째로 밀려 있어서 순서를 다시 정해야 했다.
버튼은 18개 화면 전부에 나온다. 화면부터 만들면 화면마다 버튼을 다시 그리게 되고,
나중에 색 하나 바꾸려면 18군데를 고쳐야 한다.
**2주차에 화면 15개를 몰아서 만들 때 조립만 하면 되는 상태**를 만드는 게 목적이다.

`design-system.md`에 "placeholder만으로 대체하지 마라"고 적혀 있는데, 문서로만 두면 지켜지지 않는다.
`label`을 필수 prop으로 두면 **빼먹는 순간 타입 오류가 난다.** 규칙을 타입으로 강제한 것이다.

## 알게 된 것

- **Node.js와 Next.js는 비교 대상이 아니다.** Node는 JS를 실행하는 런타임이고,
  Next.js는 그 위에서 도는 프레임워크다. 백엔드의 Express도 같은 층에 있다.
  "백엔드가 Node니까 프론트도 맞춰야 하나"를 고민했는데 애초에 상관없는 문제였다.
- **`next/font`의 폰트 목록에 주아체의 korean 서브셋이 빠져 있다.** `subsets: ["latin"]`으로 두면
  한글 글리프를 아예 안 받아와서 한글이 대체 폰트로 나온다. `subsets`를 생략하고
  `preload: false`로 둬야 구글이 주는 CSS 전체(한글 포함)를 쓴다. 빌드 결과에서 `AC00` 범위로 확인했다.
- **문서의 폴더 구조 `src/pages/`가 App Router와 충돌한다.** Next.js가 그 이름을 구형 라우터로
  인식한다. 프로젝트를 만들면서 발견해서 `frontend.md`를 `src/app/`으로 고쳤다.
- 탭에 뜨던 파비콘은 `create-next-app`이 넣은 **버셀 로고**였다. Next.js를 버셀이 만들어서 기본값이 그렇다.
