# 디자인 시스템

## 대원칙

1. **색·간격·글자 크기를 코드에 직접 쓰지 마라.** 반드시 토큰(CSS 변수)을 쓴다.
   - 금지: `color: #ff6b35`, `padding: 13px`, `font-size: 15px`
   - 허용: `color: var(--text-brand)`, `padding: var(--space-3)`
2. **토큰에 없는 값이 필요하면 만들지 말고 물어봐라.** 새 색을 추가하는 건 디자인 결정이다.
3. **다크 모드를 구현하지 마라.** 앱인토스 미니앱은 다크 모드를 지원하지 않는다. 라이트 모드 단일 기준이다.
   - 금지하는 건 `prefers-color-scheme`으로 **화면 전체가 뒤집히는 것**이다.
   - **어두운 화면 한 장을 그리는 건 다크 모드가 아니다.** `18 홈 / 영업 종료`처럼 장면에 맞춰
     의도적으로 어둡게 칠한 화면은 만들어도 된다. 시스템 설정과 무관하게 항상 그 색이기 때문이다.
4. 토큰 이름은 피그마 변수 이름과 1:1로 일치시킨다. 피그마 `brand/primary` → CSS `--brand-primary`.

## TDS 전환을 염두에 둔 구조

나중에 토스 디자인 시스템(TDS)으로 갈아탈 가능성이 있다. 그래서 **원시값과 의미값을 분리한다.**

```
원시(primitive)   --orange-500: #ff6b35     ← 실제 색값. 여기만 바뀐다
의미(semantic)    --brand-primary: var(--orange-500)   ← 컴포넌트는 이것만 쓴다
```

컴포넌트 코드는 **의미 토큰만** 참조한다. 그래야 TDS로 옮길 때 의미 토큰의 우변만 갈아끼우면 끝난다.

**TDS 토큰 이름을 추측해서 쓰지 마라.** 실제 이름은 앱인토스 개발자센터의 디자인 가이드를 보고 확인한 뒤에 매핑한다. 지금은 위 구조만 지킨다.

## 색상 토큰

피그마 파일의 하드코딩된 색 31종을 아래 18종으로 통합한다. **목록에 없는 색은 쓰지 않는다.**

> 처음 15종으로 정리했고, 2026-09-20에 어두운 면 3종을 더해 18종이 됐다.

### 브랜드

| 토큰 | 값 | 용도 |
|---|---|---|
| `--brand-primary` | `#ff6b35` | 주 버튼 배경, 강조 요소 |
| `--brand-primary-subtle` | `#fff4ed` | 연한 배경, 선택 상태 |
| `--brand-primary-text` | `#c2410c` | **주황색 글자가 필요할 때만** 이걸 쓴다 |

> `#ff6b35`를 글자색으로 쓰면 흰 배경 대비 2.8:1로 접근성 기준(4.5:1) 미달이다.
> 주황은 배경으로만 쓰고 그 위에는 **어두운 글자(`--text-on-brand`)**를 올린다. 글자를 주황으로 해야 하면 `--brand-primary-text`.

#### 주황 위 글자를 흰색에서 어두운 색으로 바꾼 이유 — 2026-11-11

원래 이 문서는 "주황 위에 흰 글씨를 올린다"고 했다. 그런데 **대비는 글자와 배경을 맞바꿔도 같은 값이다.**
흰 배경 위 주황 글자가 2.84:1이면 주황 배경 위 흰 글자도 2.84:1이다. 주황 글자를 금지하면서
주 버튼 글자는 전부 같은 미달 값으로 두고 있었다. 야외 햇빛 아래에서 가장 중요한 버튼이 가장 안 읽혔다.

| 방법 | 대비 | 판단 |
|---|---|---|
| 주황 위 흰 글자 (전) | 2.84:1 | 미달 |
| **주황 위 `--gray-900` 글자 (지금)** | **6.14:1** | 브랜드 주황은 그대로. 토큰 우변 한 줄만 바뀐다 |
| 주황을 `--orange-700`으로 어둡게 + 흰 글자 | 5.18:1 | 버튼·토글·탭 막대가 전부 벽돌색이 된다. 택하지 않음 |

새 색은 만들지 않았다. `--text-on-brand`가 가리키는 원시 토큰만 `--gray-0`에서 `--gray-900`으로 바꿨다.
카카오 버튼(노랑 위 검정 글자)과 같은 문법이 됐다.

### 텍스트

| 토큰 | 값 | 용도 |
|---|---|---|
| `--text-default` | `#1a1a1a` | 본문, 제목. 순수 검정(`#000`)은 쓰지 않는다 |
| `--text-secondary` | `#555555` | 보조 설명 |
| `--text-muted` | `#666666` | 흐린 라벨. 기존 `#888888`은 대비 미달이라 상향 조정됨 |
| `--text-on-brand` | `#1a1a1a` | 주황 배경 위 글자. 6.14:1 (2026-11-11에 `#ffffff`에서 바꿈) |

### 배경 · 선

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-surface` | `#ffffff` | 카드, 시트, 모달 배경 |
| `--bg-page` | `#f5f5f5` | 페이지 배경 |
| `--border-default` | `#e0e0e0` | 구분선, 카드 테두리 |
| `--border-strong` | `#cccccc` | 입력창 기본 테두리 |
| `--border-focus` | `#c2410c` | 입력창 포커스 테두리 · 포커스 링 |

#### 입력창 테두리를 진하게 하지 않는 이유 — 2026-09-08 판단

`--border-strong` `#cccccc`는 흰 배경 대비 **1.6:1**이다. WCAG 1.4.11(비텍스트 대비)이 요구하는 3:1에 미달한다.
그런데 **테두리를 진하게 올리지 않는다.** TDS를 비롯한 국내 모바일 UI는 입력창을 진한 선으로 두르지 않고, 면(fill)과 여백으로 구분하는 방향이기 때문이다. 선을 `#949494`까지 올리면 3:1은 넘기지만 화면이 무거워지고 나중에 TDS로 옮길 때 다시 걷어내야 한다.

대신 **아래 세 가지를 지켜서 접근성을 확보한다.** 1.4.11은 테두리가 컨트롤을 식별하는 *유일한* 수단일 때 3:1을 요구하므로, 다른 식별 수단이 있으면 충족된다.

1. **입력창은 반드시 배경색으로 구분한다.** 페이지 배경이 `--bg-page`면 입력창은 `--bg-surface`, 카드 위(`--bg-surface`)에 놓이면 입력창은 `--bg-page`. 면이 다르면 테두리가 없어도 컨트롤임을 안다.
2. **라벨을 반드시 붙인다.** placeholder만으로 대체하지 마라. 입력하면 사라져서 무슨 칸인지 알 수 없게 된다.
3. **포커스는 `--border-focus`로 2px.** `#c2410c`는 흰 배경 대비 **5.18:1**이라 충분하다.
   `--brand-primary` `#ff6b35`를 포커스 링에 쓰지 마라. 흰 배경 대비 **2.8:1**로 3:1에 미달한다.

### 어두운 면 — 2026-09-20 추가

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-inverse` | `#1a1a1a` | 어두운 화면 배경 |
| `--text-on-inverse` | `#ffffff` | 어두운 배경 위 글자 |
| `--text-on-inverse-muted` | `#cccccc` | 어두운 배경 위 보조 설명. 검은 배경 대비 11:1 |

**다크 모드가 아니다.** 시스템 설정과 무관하게 항상 어둡고, 다른 화면은 그대로 밝다.
쓰는 곳은 둘뿐이다.

1. `18 홈 / 영업 종료` 화면. 하루를 마무리하는 화면이라 그 장면만 어둡게 그린 것이다
2. **토스트** (2026-11-11 추가). 이 앱의 버튼·카드는 전부 밝은 면이다. 토스트를 밝은 면으로 그리면 버튼과 구별되지 않는다.
   어두운 면 하나로 "잠깐 뜨는 알림이고 누르는 것이 아니다"를 전한다

그 밖의 화면이나 카드를 어둡게 칠하지 마라.

새 색값은 하나도 만들지 않았다. 셋 다 이미 있는 원시 토큰(`--gray-900` `--gray-0` `--gray-400`)을 가리킨다.
어두운 면 위의 카드는 `color-mix(in srgb, var(--text-on-inverse) 8%, transparent)`로 한 겹 띄운다. 이것도 새 색이 아니다.

### 상태

| 토큰 | 값 | 용도 |
|---|---|---|
| `--status-open` | `#2e8b2e` | "영업 중" **표시** — 점, 아이콘. 글자색으로 쓰지 않는다 |
| `--status-open-bg` | `#e8f8e8` | "영업 중" **면** — 배지, 사장님 홈 영업 중 머리말 |
| `--info` | `#3b82f6` | 정보 표시. **글자색으로 쓰지 않는다** (흰 배경 대비 3.68:1) |

#### 초록과 파랑을 글자색으로 쓰지 않는 이유 — 2026-11-11

| 조합 | 대비 | 기준(4.5:1) |
|---|---|---|
| `--status-open` 글자 on `--status-open-bg` (전의 "영업 중" 배지) | 3.92:1 | 미달 |
| `--status-open` 글자 on 흰 배경 | 4.33:1 | 미달 |
| `--info` 글자 on 흰 배경 (전의 "내 가게 페이지 미리보기") | 3.68:1 | 미달 |

그래서 **상태 글자는 `--text-default`로 쓰고, 색은 면과 점이 맡는다.**
점·아이콘은 글자가 아니라 3:1이면 되므로 `--status-open`을 그대로 쓴다.

- "영업 중" 배지: 초록 면 + 꽉 찬 초록 점 + 본문 크기(`--font-body`) 글자
- "준비 중" 배지: 회색 면 + **속이 빈** 점. 흑백으로 봐도 영업 중과 모양이 다르다
- 사장님 홈 머리말: 준비 중은 주황 면(`--brand-primary-subtle`), 영업 중은 초록 면(`--status-open-bg`)
- 링크는 색이 아니라 **밑줄**로 알린다 (`--text-secondary` + 밑줄)

상태 글자를 본문 크기로 키운 것도 같은 날이다. 전에는 12px(`--font-label`)이라 화면에서 가장 작은 글자였는데,
손님도 사장님도 가장 먼저 찾는 정보가 "지금 열려 있나"다.

## 타이포그래피

본문 서체는 **주아체**. **Regular 한 가지 굵기뿐이다.**

- `font-weight: bold` 를 쓰지 마라. 렌더링이 깨지거나 가짜 굵기(faux bold)가 적용된다.
- 위계는 **크기와 색으로만** 만든다.

| 토큰 | 크기 / 행간 | 용도 |
|---|---|---|
| `--font-display` | 28 / 36 | 화면 대표 제목 |
| `--font-title` | 22 / 30 | 섹션 제목 |
| `--font-subtitle` | 18 / 26 | 카드 제목, 메뉴명 |
| `--font-body` | 16 / 24 | 본문 |
| `--font-caption` | 14 / 20 | 보조 설명 |
| `--font-label` | 12 / 16 | 작은 표시("품절" 배지), 라벨. **영업 상태 배지에는 쓰지 않는다** — 본문 크기로 쓴다 |

## 컴포넌트

아래 5개는 피그마 컴포넌트와 이름·variant가 일치해야 한다. **같은 역할의 UI를 새로 만들지 말고 이걸 재사용하라.**

| 컴포넌트 | variant | state |
|---|---|---|
| `Button` | `primary` `secondary` `kakao` `google` | `default` `pressed` `disabled` `loading` |
| `BottomNav` | — (사장님 전용) | 선택된 탭: `home` `location` `menu` |
| `MenuCard` | — | `available` `soldout` |
| `TextInput` | — | `default` `focus` `error` |
| `Toggle` | — | `on` `off` `disabled` |

**`BottomNav`는 사장님 화면에만 쓴다. (확정 — 2026-09-16)**
원래 `owner` `customer` 두 variant였지만 손님 화면은 하단 탭 없이 지도 + 시트 구조로 가므로 `customer`를 없앴다.
탭은 **사장님 홈 · 위치 정하기 · 메뉴 정하기** 3개다.

- "손님 보기"는 탭이 아니다. 홈 화면의 **"내 가게 페이지 미리보기"** 버튼으로 바꾼다.
  다른 트럭까지 보이는 주변 지도(`/nearby`)가 아니라 **내 트럭의 공유 링크 페이지(`/t/:slug`)만** 연다.
  손님에게 링크를 보내기 전에 위치·메뉴가 제대로 보이는지 확인하는 용도다
- 설정·로그아웃은 탭이 아니다. 자주 누르지 않으므로 홈 상단 아이콘으로 둔다
- 피그마 프레임에는 아직 4탭(손님 보기 포함)으로 그려져 있다. 코드가 기준이고 피그마는 나중에 맞춘다

### 쓰는 법 — 2026-11-11 디자인 검토에서 정한 것

근거와 고치기 전 모습은 `docs/design.md`에 있다. 여기에는 지켜야 할 것만 적는다.

**`Toggle`의 라벨은 "켜졌을 때 참이 되는 말"로 쓴다.**
"품절", "알림 받기"처럼 쓴다. "판매 상태"처럼 중립적인 말을 쓰면 꺼진 스위치 옆에 "판매 중"이 붙어
"판매 상태가 꺼져 있다"로 읽힌다. 메뉴 카드의 토글은 라벨이 "품절"이고, 켜지면 품절이다.

**`MenuCard`는 두 모양이다.**
- 손님(읽기 전용): 메뉴명 · "품절" 배지 · 가격이 한 줄
- 사장님(토글 있음): 왼쪽에 메뉴명과 가격, 오른쪽에 "품절" 토글. 피그마 `08`과 같은 한 줄 카드다

**비활성 버튼 안에 안내 문구를 넣지 마라.**
비활성 버튼은 통째로 흐려진다(불투명도 0.4). 그 안의 글자는 대비가 1.6:1까지 떨어진다.
- 버튼 문구는 켜져 있든 꺼져 있든 **같은 말**이다. "지금 오픈하기"
- 왜 못 누르는지, 무엇이 남았는지는 **버튼 밖의 일반 글자**로 쓴다. "메뉴만 정하면 오픈할 수 있어요"
- 아직 없는 기능도 같다. 버튼은 비활성으로 두고 그 아래에 "아직 준비하고 있는 기능이에요"라고 쓴다

**토스트는 작고 어두운 알약이다. 하단 버튼을 가리지 않는다.**
- 모양: **뒤가 살짝 비치는** 어두운 면(`--bg-inverse`를 80%만 칠하고 뒤쪽은 흐리게) + 흰 글자(`--text-on-inverse`).
  글자 길이만큼만 차지한다. 폭을 채우지 않는다. 가장 밝은 배경 위에서도 글자 대비는 9.1:1이다
- 자리: 하단 버튼이 있는 화면에서는 그 버튼 **바로 위**. 전에는 버튼 자리에 같은 크기의 흰 상자로 겹쳐 띄워서 버튼처럼 보였다
- 앞에 아이콘을 둔다. 끝난 일은 체크, 못 한 일과 안내는 느낌표 — `toast(문구, "notice")`
- 창(`BottomSheet`)이 열려 있을 때는 토스트가 뒤에 깔린다. 창 안에 글자로 보인다 (2026-09-22 결정 그대로)

**고르는 화면은 맨 아래 주 버튼으로 끝낸다.**
위치 정하기는 "이 위치로 정하기", 메뉴 정하기는 "이 메뉴로 정하기". 누르면 홈으로 돌아가 오픈 버튼 앞에 선다.
메뉴는 넣는 순간 이미 저장되므로 이 버튼은 저장이 아니라 **마무리**다. 누르지 않고 탭으로 나가도 잃는 것은 없다.

이 버튼은 **화면 아래(하단 탭 바로 위)에 붙어 있다.** 목록이 길거나 폰 세로가 짧아도 스크롤 없이 항상 보인다.
`position: sticky`로 붙이고, 목록은 그 뒤로 지나가며 옅어진다.
글자를 입력하는 화면에서는 붙이지 않는다 — 키보드가 올라오면 버튼이 입력창을 가린다(메뉴 추가 입력 카드가 열려 있을 때는 이 버튼을 그리지 않는다).

**한 화면에 주 버튼(주황)은 하나만 둔다. 카카오 버튼(노랑)이 있으면 그것이 주 행동이다.**
주황과 노랑이 나란히 있으면 강조색 둘이 겨룬다. 오픈 완료 시트와 영업 중 홈의 공유 카드는
카카오톡(주) → 링크 복사(`secondary`) 순서다.

**확인창의 첫 포커스는 취소 버튼이다.** 취소 버튼에 `data-autofocus`를 달면 `BottomSheet`가 연 직후에 포커스를 옮긴다.
`autoFocus`는 `<dialog>` 안에서 동작하지 않는다.

## 레이아웃

- 기준 폭 393px, **최소 지원 폭 360px.** 360px에서 깨지지 않아야 한다.
- 텍스트가 길어지면 밀리지 않도록 flex 기반으로 짠다. 고정 폭·고정 높이를 쓰지 마라.
- 메뉴명은 **15자 이상**으로 테스트한다. "매콤 크림치즈 타코야끼 세트" 같은 이름이 실제로 들어온다.
- 웹뷰 환경이므로 상·하단 안전영역을 `env(safe-area-inset-*)`로 처리한다.

## 접근성

- 텍스트 대비 4.5:1 이상. **야외 햇빛 아래에서 쓰는 앱이라 특히 중요하다.**
- 터치 영역 최소 44×44px.
- 상태를 색으로만 표현하지 마라. "영업 중 / 준비 중"은 색 + 글자를 함께 쓴다.
