# 디자인 문서

이 화면들이 **왜 이렇게 생겼는지**를 적은 기록이다.

- 지켜야 할 규칙(토큰, 컴포넌트, 접근성 기준)은 [`design-system.md`](design-system.md)에 있다. 규칙은 그 문서가 기준이다
- 이 문서는 규칙이 아니다. 누구를 위해 디자인했고, 무엇을 판단했고, 검토에서 무엇이 드러나 어떻게 고쳤는지를 남긴다
- 마지막으로 고친 날: 2026-11-11

## 1. 누구를 위해 디자인하나

| 사용자 | 쓰는 상황 | 해야 하는 일 | 잘됐다고 볼 기준 |
|---|---|---|---|
| 사장님 | 트럭 앞에서 장사 준비 중. 야외 햇빛, 한 손, 짧은 시간 | 오늘 위치·메뉴를 정하고 오픈해서 링크를 보낸다. 끝나면 마감한다 | 로그인 뒤 10탭 안팎으로 오픈하고, 1탭 더해 카카오톡으로 보낸다. 어느 단계에서도 막히지 않는다 |
| 손님 | 카카오톡 방에서 링크를 누름. 앱 설치 없음, 처음 보는 화면 | 지금 가도 되는지, 어디인지, 뭘 파는지 판단한다 | 스크롤 없이 첫 화면에서 영업 여부·위치·마감 시각·메뉴·가격이 보인다. 영업 여부가 가장 먼저 읽힌다 |

사장님 흐름은 실제로 눌러서 셌다(2026-11-11). 로그인 2탭, 위치 3탭, 영업시간 2탭, 메뉴 3탭, 오픈 1탭으로 **11탭**이다.
손님 페이지는 360×780 화면 한 장에 전부 들어온다.

## 2. 화면 구조

```
/                시작 — 로고 + "사장님으로 시작하기"
/login           사장님 로그인 (카카오 · 구글)
/owner           사장님 홈 ─ 오늘 영업의 상태판
  ├ /owner/location   위치 정하기
  └ /owner/menu       메뉴 정하기
/t/:slug         손님 공유 페이지 — 로그인 없이 열리는 한 장
```

**사장님 홈은 상태판이다.** 오늘 세션의 상태 하나로 화면이 갈린다.

| 상태 | 머리말 | 하단 버튼 |
|---|---|---|
| 아직 다 정하지 않음 | 주황 면 · "오늘 영업 준비되셨나요?" | 남은 것 안내 한 줄 + "지금 오픈하기"(비활성) |
| 다 정함 | 주황 면 · "준비 끝! 이제 오픈만 하면 돼요" | "지금 오픈하기" |
| 영업 중 | **초록 면** · "지금 영업 중" 배지 | 공유 카드(카카오톡 · 복사) + "오늘 영업 마감하기" |
| 영업 종료 | **어두운 화면** · "오늘도 영업 수고하셨어요" | 없음 |

**손님 페이지는 지도 없는 한 장이다.** 영업 상태 → 트럭 이름 → 영업시간·남은 시간 → 오늘 위치와 길찾기 → 오늘의 메뉴 순서다.
지도를 넣지 않은 대신 "카카오맵으로 길찾기"가 바로 지도 앱을 연다.

## 3. 디자인 원칙

화면을 고칠 때마다 되돌아오는 다섯 가지다.

1. **상태가 가장 먼저 읽혀야 한다.** 손님의 첫 질문도 사장님의 첫 질문도 "지금 열려 있나"다. 상태는 본문 크기 글자와 면 색으로 말한다
2. **색은 면과 점이 맡고, 글자는 어두운 색으로 쓴다.** 초록·파랑·주황 글자는 대비가 모자란다. 야외 햇빛 아래에서 쓰는 앱이다
3. **주황은 "지금 누를 것"에만 쓴다.** 한 화면에 주 버튼은 하나다
4. **흐려진 곳에 말을 담지 않는다.** 비활성 버튼 안의 글자는 읽히지 않는다. 안내는 버튼 밖에 쓴다
5. **숨기지 않고 보여 준다.** 품절 메뉴는 목록에서 빼지 않고 회색 + "품절"로 남긴다. 아직 없는 기능은 비활성으로 두고 그렇다고 말한다

여기에 처음부터 지켜 온 제약이 둘 있다. **새 색을 만들지 않는다**(토큰 18종 안에서 해결한다), **굵기를 쓰지 않는다**(주아체는 Regular 하나뿐이라 위계는 크기와 색으로만 만든다).

### 고친 것 — 전과 후

#### D-01 메뉴 화면의 목록 = 오늘 팔 메뉴

| | 전 | 후 |
|---|---|---|
| 처음 목록 | 트럭 전체 메뉴 4개가 들어 있음 | 비어 있음 (피그마 `07`과 같다) |
| 어제 메뉴 불러오기 | 홈만 채워지고 목록은 그대로. 목록 4개, 홈 "외 2개" | 목록과 홈이 같이 채워짐 |
| 메뉴 추가하기 | 목록에만 생김. 홈은 "아직 설정하지 않았어요" | 목록과 홈이 같이 채워짐. 오픈 버튼이 켜짐 |

품절을 그날 스냅샷에만 기록한다는 규칙(`product-rules.md` "품절")과도 맞게 됐다. 전에는 트럭 전체 메뉴에 품절을 걸고 있었다.
실제 API에서 두 목록을 어떻게 이을지는 백엔드 답을 기다리는 중이라 **목데이터 안에서만** 맞췄다.

#### D-02 품절 토글

```
전                                    후
┌───────────────────────────────┐    ┌───────────────────────────────┐
│ 타코야끼 8알           5,000원 │    │ 타코야끼 8알        품절 (○ ) │
│ ───────────────────────────── │    │ 5,000원                       │
│ 판매 상태       판매 중 (○ )   │    └───────────────────────────────┘
└───────────────────────────────┘
```

라벨을 "품절"로 바꿔서 켜짐 = 품절이 됐다. 피그마 `08`의 한 줄 카드로 돌아가 카드 높이가 절반이 됐고,
메뉴 4개에서도 "메뉴 추가하기"가 첫 화면에 들어온다. 켜지면 왼쪽에 "품절" 배지가 붙고 메뉴명이 흐려진다.

#### D-03 주 버튼 글자

주황(`#ff6b35`) 위 흰 글자 2.84:1 → 어두운 글자(`#1a1a1a`) **6.14:1**.
규칙 문서가 "주황 글자는 2.8:1이라 금지"라면서 "주황 위에 흰 글씨를 올린다"고 한 것이 같은 값의 모순이었다.
브랜드 주황은 그대로 두고 `--text-on-brand` 한 줄만 바꿨다. 주황을 어둡게 하는 안(5.18:1)은 앱 전체가 벽돌색이 되어 택하지 않았다.

#### D-04 영업 상태

- 상태 배지를 12px에서 **본문 크기(16px)**로 키웠다. 글자는 어두운 색, 초록은 면과 점이 맡는다
- 준비 중 배지는 **속이 빈 점**이다. 흑백으로 봐도 영업 중(꽉 찬 점)과 모양이 다르다
- 사장님 홈은 영업 중이 되면 머리말이 **초록 면**이 된다. 전에는 주황 면이 사라지고 12px 배지만 남았다

피그마 `15`는 진한 초록 면 + 흰 글자다. 그 조합은 4.33:1이라 9/15에 "미결정"으로 남겨 뒀었다.
같은 뜻을 연한 초록 면 + 어두운 글자로 옮겨, 준비 중의 주황 면과 짝이 맞게 했다.

#### D-05 안내는 버튼 밖에

```
전                                    후
                                      메뉴만 정하면 오픈할 수 있어요
[ 위치와 메뉴를 먼저 설정해 주세요 ]   [        🎉 지금 오픈하기        ]
  (비활성, 1.62:1)                      (비활성)
```

버튼 문구는 켜져 있든 꺼져 있든 같은 말이다. 무엇이 남았는지는 버튼 위의 일반 글자가 말하고, 남은 항목에 따라 바뀐다.
손님 페이지의 "오픈 알림 받기"와 시작 화면의 "손님으로 둘러보기"도 같은 방법으로 고쳤다. "준비 중" 칩을 버튼 안에서 빼서 버튼 아래 글자로 옮겼다.

#### D-06 토스트

```
전                                    후
                                            ( ✓ 위치를 정했어요 )     ← 작고 어두운 알약
[      위치를 설정했어요      ]        [      🎉 지금 오픈하기      ]
  (버튼 자리를 덮은 흰 상자)
```

- **작고 어두운 알약**으로 바꿨다. 글자 길이만큼만 차지한다. 전에는 버튼과 크기·테두리·모서리가 같은 흰 상자였다
- 뒤가 살짝 비친다. 어두운 면을 80%만 칠하고 뒤쪽은 흐리게 했다. 꽉 막힌 검정보다 화면 위에 잠깐 얹힌 느낌이 난다
- 하단 버튼 **위**에 띄운다. 전에는 버튼 자리에 겹쳐 띄워서, 그 순간 눌러야 할 버튼을 2.5초 가렸다
- 앞에 아이콘을 둔다. 끝난 일은 체크, 못 한 일과 안내는 느낌표다

9/22에 "버튼 자리를 잠깐 알림이 쓰는 모양"으로 정했던 것을 뒤집었다. 그때는 토스트가 버튼을 반쯤 덮는 문제를 풀려던 것이었는데,
완전히 덮으니 **알림이 버튼인 척하는 모양**이 됐다. 처음에는 흰 상자를 버튼 위로 올리기만 했지만 그래도 버튼이 두 개 쌓인 것처럼 보였다.
이 앱의 버튼·카드는 전부 밝은 면이라, 어두운 면 하나로 "누르는 것이 아니다"를 전하는 쪽이 자연스럽다.
그래서 영업 종료 화면에만 쓰던 어두운 면 토큰을 토스트에도 쓰기로 규칙을 고쳤다. 새 색은 만들지 않았다.

#### 메뉴 정하기의 마무리 버튼

메뉴를 다 넣고 나서 "끝났다"를 누를 곳이 없었다. 하단 탭을 직접 눌러 홈으로 가야 했다.
위치 정하기는 "이 위치로 정하기"로 끝나는데 메뉴 정하기만 끝이 없었던 셈이다.

맨 아래에 **"이 메뉴로 정하기"**를 뒀다. 누르면 "메뉴 3개를 정했어요"와 함께 홈으로 돌아가 오픈 버튼 앞에 선다.
메뉴는 넣는 순간 이미 저장되므로 이 버튼은 저장이 아니라 마무리다. 피그마의 "저장" 버튼을 뺐던 이유
(눌러야 저장되면 "추가했는데 저장은 안 된" 상태가 생긴다)는 그대로 지켰다.

#### 고르는 화면의 하단 버튼은 항상 보인다

위치 정하기의 "이 위치로 정하기"는 목록 끝에 흐름대로 놓여 있었다. 세로가 짧은 폰(360×640)에서는
장소를 고른 뒤 버튼을 찾아 스크롤해야 했다.

버튼을 화면 아래, 하단 탭 바로 위에 붙였다. 목록은 그 뒤로 지나가며 옅어진다.
메뉴 정하기의 "이 메뉴로 정하기"도 같은 방법이다. 세로가 짧은 화면에서는 지도가 화면 높이의 4분의 1을 넘지 않게 해서 목록 자리를 남겼다.

전에 하단 버튼을 붙이지 않았던 이유는 "키보드가 올라오면 가려진다"였다. 위치 화면에는 글자 입력이 없고,
메뉴 화면은 입력 카드가 열려 있는 동안 이 버튼을 그리지 않으므로 그 걱정이 해당하지 않는다.

#### 영업 중 홈의 줄 색

영업 중에는 위치·영업시간·메뉴 줄을 주황으로 칠하지 않고 흰 면 + 어두운 글자로 둔다(피그마 `15`와 같다).
주황 면은 "하나씩 채워 가는 중"을 보여 주는 표시인데 오픈한 뒤에는 그 뜻이 끝났다.
그대로 두면 초록 머리말, 주황 줄, 노랑 카카오 버튼이 한 화면에서 겨뤘다.

#### D-07 영업 중 홈의 공유

- 공유 카드에 "카카오톡으로 공유하기"를 넣었다. 전에는 오픈 직후 시트에만 있어서 시트를 닫으면 복사만 남았다
- 시트와 카드 모두 **카카오톡(주) → 링크 복사(보조)** 순서다. 전에는 주황 "복사"와 노랑 "카카오톡"이 같은 무게로 겨뤘다
- "내 가게 페이지 미리보기"는 파란 글자(3.68:1)에서 밑줄 + 어두운 글자(7.46:1)로 바꿨다

#### D-09 확인창 포커스

마감 확인창을 열면 포커스가 "마감하기"에 있었다. "오늘은 다시 열 수 없어요"인 동작이라 Enter 한 번에 하루가 끝난다.
`<dialog>`는 열릴 때 첫 버튼에 포커스를 주고, React의 `autoFocus`는 그 안에서 동작하지 않는다.
창을 연 직후 취소 버튼으로 포커스를 직접 옮기게 했다.

#### D-12 문구

| 전 | 후 |
|---|---|
| "이 위치로 설정" · "위치를 설정했어요" · "아직 설정하지 않았어요" · "영업시간 설정" | "이 위치로 정하기" · "위치를 정했어요" · "아직 정하지 않았어요" · "영업시간 정하기" |
| 다 채운 뒤에도 "오늘 영업 준비되셨나요?" | "준비 끝! 이제 오픈만 하면 돼요" |
| "손님 초대 링크" | "손님에게 공유할 링크" |
| 알림 버튼 안의 "준비 중" (영업 상태 배지와 같은 말) | 버튼 아래 "오픈 알림은 아직 준비하고 있는 기능이에요" |

탭 이름이 "위치 정하기" · "메뉴 정하기"라 그 단어로 맞췄다.

## 7. 확인하지 못한 것

- **피그마 원본.** 계정 좌석이 보기 전용이라 열 수 없었다. 대조는 `docs/assets/`의 화면흐름도 이미지로만 했다.
  변수·컴포넌트 수, 실제 색값, 온보딩 3장은 대조하지 못했다
- **카카오맵 지도와 핀.** 검토한 주소가 카카오 콘솔에 등록되지 않아 "지도를 불러오지 못했어요" 화면만 봤다.
  핀 안의 아이콘 색도 `--text-on-brand`를 따라 어두운 색으로 바뀌었으니 배포 주소에서 확인한다
- **실제 폰.** 햇빛, 키보드가 올라온 메뉴 추가 폼, 안전영역, 카카오톡의 실제 미리보기 크기
- **스크린리더.** 실제 낭독은 듣지 못했고 역할·속성으로만 판단했다
